# Implementation Plan: Runner Isolation Options (network / pull / uid)

**Branch**: `claude/kontinuance-cross-app-alignment-w3hk0o` | **Date**: 2026-07-25 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/030-runner-options/spec.md`

## Summary

Add a nested `RunnerOptions` (network / pull policy / user mapping) to `Step`, applied by
`DockerStepSandbox` when a step names an `image` (024). `dockerRunArgv` gains `--network <net>`,
`--pull <policy>`, and — when `mapUser` is set and a host uid/gid resolves — `-u <hostUser>`, inserted before
the workspace mount; the host user is probed once (owner of a temp file, portable, no `com.sun`) and injected
as data so the argv stays pure/unit-testable. `Step.init` guards that runner options require an image (else a
silent, non-isolated host run). The descriptor gains a strict `runner: { network, pull, mapUser }` block and
the DSL exposes it (generated `runner` var + `TypedStepOptions.runner`), producing identical models. Additive
and dependency-free; a step with no runner options is byte-for-byte the 024 wrapper.

## Technical Context

**Language/Version**: Kotlin/JDK 21 (`:engine`), konstellation KSP DSL.

**Primary Dependencies**: none new — `docker` is a host CLI; uid probe uses `java.nio` unix attributes.

**Storage**: none.

**Testing**: `DockerStepSandboxTest` (argv with network/pull/`-u`; `mapUser` no-op without a host user;
no-options argv == 024 wrapper), `RunnerOptionsDescriptorTest` (descriptor `runner` parses; DSL parity;
unknown pull/runner key rejected; runner-without-image rejected).

**Constraints**: options apply only in a container (image guardrail); argv pure (host user as data);
`mapUser` a safe no-op without a resolvable uid; strict parsing; no new dependency; no-options behavior
unchanged.

**Scale/Scope**: `model/RunnerOptions.kt` (new) + `Step.kt` (`runner` field + guardrail);
`execution/DockerStepSandbox.kt` (flags + host-user probe); `descriptor/PipelineDescriptor.kt` (runner
parse) ; `dsl/steps/TypedStepOptions.kt` + `TypedStepSupport.kt` (runner passthrough); tests + docs.

**Structure Decision**: Nest the options in `RunnerOptions` (rather than more flat `Step` fields) so the
isolation knobs group cleanly and only surface with an image. Keep the argv pure by injecting the host user
as data, and guard runner-without-image at model construction so a missing image can never masquerade as
isolation.
