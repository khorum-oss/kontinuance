# Implementation Plan: Docker Runner Isolation (per-step image)

**Branch**: `claude/kontinuance-cross-app-alignment-w3hk0o` | **Date**: 2026-07-25 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/024-runner-isolation/spec.md`

## Summary

Introduce a `StepSandbox` seam in the engine's process-execution layer that wraps a step's launch argv. The
default `DockerStepSandbox` wraps the command in `docker run --rm -v <workspace>:/workspace -w /workspace
[-e SECRET…] <image> <argv>` when a step names an image (`Step.image`), and is the identity otherwise — so
isolation is opt-in per step and host steps are unchanged. All process executors share one injected sandbox
(wired through `PipelineEngine.default`), and the wrapped command reuses the existing `ProcessStepExecutor`
machinery, so an isolated step inherits the same timeout/masking/cancellation/tree-kill. The step-level
`image:` is added to the model (`@GeneratedDsl Step`, so the DSL builder regenerates), the strict descriptor
parser, and the typed-step DSL options. Secrets are forwarded **by name only** so values never hit the argv.
`docker` stays a host CLI (no new dependency).

## Technical Context

**Language/Version**: Kotlin/JDK 21 (`:engine`), konstellation KSP DSL generation.

**Primary Dependencies**: none new — `docker` is invoked as a host CLI binary, never a Gradle dependency.

**Storage**: none.

**Testing**: `DockerStepSandboxTest` (pure argv: image → docker run with mount/workdir/`-e NAME`; no image →
identity; secret value absent from argv), `RunnerIsolationTest` (full engine path with an injected recording
sandbox — the step's image + base argv flow through; host steps carry a null image), `RunnerImageDescriptor
Test` (YAML `image:` parses; DSL/descriptor equal models; v0 `step { image = … }`; blank rejected). The real
container run needs a Docker daemon and is exercised in CI / on real hosts (documented, like the sandbox
demo's honesty).

**Constraints**: behavior-preserving unless a step opts in; secrets never on the argv; `docker` as CLI only;
no new dependency; generated DSL validated by regenerating + building (Principle IV).

**Scale/Scope**: `engine/execution/StepSandbox.kt` + `DockerStepSandbox.kt` (new); `ProcessStepExecutor` +
the 5 process executors + `PipelineEngine.default` (thread the sandbox); `model/Step.kt` (`image` field);
`descriptor/PipelineDescriptor.kt` (`image` key); `dsl/steps/TypedStepOptions.kt` + `TypedStepSupport.kt`
(`image` passthrough); tests + docs.

```text
engine/.../execution/DockerStepSandboxTest.kt (test)   # NEW — pure argv + no-secret-leak

engine/.../descriptor/RunnerImageDescriptorTest.kt (test) # NEW — descriptor/DSL parity + blank rejection
docs/getting-started.md, docs/roadmap.md         # EDIT — per-step image runner isolation (024)
```

**Structure Decision**: Put isolation at the `ProcessStepExecutor` argv boundary behind a `StepSandbox`
interface so every process step type inherits it uniformly and a future Kubernetes/other backend can replace
`DockerStepSandbox` without touching the executors. Gate it per step on `Step.image` so it is opt-in and the
host path is byte-for-byte unchanged.
